# 压缩规则参考

## 核心原则：有损压缩，保留信号

压缩不是完整归档。目标是让下一次会话的 AI 能用最少上下文快速进入状态。

## 保留（Retain）— 必须写入压缩摘要

1. **架构/设计决策**
   - "决定用 X 方案而非 Y 方案，因为..."
   - 模块划分变更、接口契约修改
   - 线程模型 / 数据流拓扑调整

2. **Bug 修复（非 trivial）**
   - 修复了影响多个模块的 Bug
   - 修复过程中发现的技术陷阱（如 Enum 身份问题）
   - 根因分析和最终修复方案

3. **模块完成标记**
   - 每个模块标记为 ✅ 的时间点
   - 测试通过数量和覆盖率

4. **API/接口变更**
   - 新增/修改的 CLI 命令
   - 新增/修改的 public API

5. **技术陷阱/踩坑记录**
   - 框架/库的边界行为
   - 平台特定问题（Windows/macOS/Linux）
   - 版本兼容性问题

## 丢弃（Discard）— 不保留

1. **过程性流水**
   - "然后运行了 pytest，3 个失败"
   - "搜索了 Stack Overflow"
   - "尝试了方案 A，不行，又试了方案 B"

2. **单文件小修改**
   - 改了一行配置
   - 更新了一条注释
   - 重命名了一个变量

3. **重复信息**
   - 与 MEMORY.md 已有的内容重复
   - 与其他日志重叠的记录

4. **外部操作记录**
   - Web 搜索的关键词和结果
   - 临时文件的路径
   - 工具调用的中间输出

## 归档格式（CHANGELOG.md）

遵循 Keep a Changelog 格式：

```markdown
## [vX.Y.Z] — YYYY-MM-DD

### Added
- 新功能 1
- 新功能 2

### Changed
- 变更 1

### Fixed
- 修复 1（附根本原因简述）

### Removed
- 移除 1
```

## STATUS.md 行数控制

- 目标：100-150 行以内
- 如果超出：优先压缩"最近变更"区域（合并为更少的条目）
- 如果仍然超出：将"已知风险"中已不活跃的条目移到 CHANGELOG
- 绝对不压缩：核心指标、当前任务、目录树快照

## 每日日志清理规则

- 30 天以内：保留，但温/冷窗口内容已压缩（原始文件可保留）
- 超过 30 天：如果已归档到 CHANGELOG.md 且 MEMORY.md 中无引用，可安全删除
- 永远不删：MEMORY.md、当天的日志
